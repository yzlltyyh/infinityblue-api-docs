视频生成任务，默认是轮询 `GET /v1/videos/{task_id}`。生产规模下，
**注册 webhook** 在模型完成时立刻接收事件 — 每个任务节省 30s-3min
轮询。

## 注册 webhook

1. Dashboard → **Webhooks** → **添加端点**
2. 输入你的 URL（必须 HTTPS）
3. 选事件：`video.task.completed`、`video.task.failed`
4. （可选）添加 HMAC 签名密钥

## Payload 格式

视频任务完成时，我们 POST 到你的端点：

```http
POST /your-webhook-endpoint HTTP/1.1
Content-Type: application/json
X-InfinityBlue-Signature: t=1700000000,v1=abc123...
X-InfinityBlue-Event: video.task.completed
User-Agent: InfinityBlue-Webhook/1.0

{
  "event": "video.task.completed",
  "created_at": 1700000000,
  "data": {
    "id": "video_abc123def456",
    "object": "video",
    "model": "seedance-2.0",
    "status": "completed",
    "progress": 100,
    "created_at": 1700000000,
    "completed_at": 1700000120,
    "expires_at": 1700003720,
    "seconds": "5",
    "size": "1280x720",
    "url": "https://cdn.infinityblue.com/videos/abc123.mp4",
    "metadata": {
      "seed": 12345
    }
  }
}
```

```json
{
  "event": "video.task.failed",

```

## 验证签名

我们用 HMAC-SHA256 签名每个 webhook。**始终**验证再信任 payload。

```python
import hmac
import hashlib

def verify_webhook(payload_bytes, signature_header, secret):
    """
    payload_bytes: 原始请求体（bytes，不要 parse JSON）
    signature_header: X-InfinityBlue-Signature header 的值
    secret: 你的 webhook 签名密钥
    """
    # 格式: "t=1700000000,v1=signature_here"
    parts = dict(p.split("=") for p in signature_header.split(","))
    timestamp = parts["t"]
    received_sig = parts["v1"]

    # 时间戳超过 5 分钟则拒绝（重放保护）
    if abs(time.time() - int(timestamp)) > 300:
        return False

    # 重新计算签名
    signed_payload = f"{timestamp}.".encode() + payload_bytes
    expected_sig = hmac.new(
        secret.encode(),
        signed_payload,
        hashlib.sha256
    ).hexdigest()

    return hmac.compare_digest(received_sig, expected_sig)
```

## 返回 2xx 确认收到

你的端点必须在 5 秒内返回 `2xx`。如果没收到 2xx，我们会指数退避重试：
- 重试 1：1 分钟后
- 重试 2：5 分钟后
- 重试 3：30 分钟后
- 重试 4：2 小时后
- 4 次后：进入 dead-letter 队列（在 dashboard 可见）

为了无重复重试，**`data.id` 是每个任务唯一的** — 让 handler
**幂等**（同一个 `id` 收到两次 = 同一个动作）。

## 常见坑

<AccordionGroup>
  <Accordion title="我收不到任何 webhook">
    检查：
    1. 端点在 5s 内返回 2xx
    2. 端点是 HTTPS（HTTP 端点被拒）
    3. webhook 注册了正确的事件
    4. dashboard 的 webhook 投递日志没有失败
  </Accordion>

  <Accordion title="签名验证失败">
    两个常见原因：
    1. 你签的是 parse 后的 JSON，不是原始 bytes。**始终**签原始 body。
       JSON 序列化可能重排键或加/删空白。
    2. 时间戳容差太紧。±5 分钟是标准。
  </Accordion>

  <Accordion title="同一个 webhook 收到 4 次">
    你的端点返回非 2xx 状态（或超时）。看 dashboard 的投递日志
    检查响应码和时序。确保快速返回 2xx（理想情况下在处理
    实际工作前 — 排队任务然后立即返回）。
  </Accordion>
</AccordionGroup>

## 最佳实践：排队处理

不要同步处理 webhook。立即返回 `200 OK`，把工作放入队列：

```python
@app.post("/webhooks/infinityblue")
async def handle_webhook(request: Request):
    payload_bytes = await request.body()
    sig = request.headers["X-InfinityBlue-Signature"]

    if not verify_webhook(payload_bytes, sig, WEBHOOK_SECRET):
        raise HTTPException(401, "Invalid signature")

    # 解析并排队，不同步处理
    event = json.loads(payload_bytes)
    await redis.enqueue("video-completed", event)

    return {"ok": True}  # 2xx in <100ms
```

worker 进程再从队列取出，从 `data.url` 下载视频，存到你自己的 S3，
更新数据库，给用户发通知等。
