---
title: "成本优化"
description: "如何在不牺牲质量的前提下降低 API 费用"
---

大多数用户通过这些技术可以砍掉 50-80% 的 API 账单。规模越大，节省越显著。

## 1. 选择能满足质量要求的最小模型

最大杠杆。同样的任务，`gpt-4o-mini` 或 `gemini-2.0-flash` 通常
能提供 `gpt-4o` 90% 的质量，成本只有 5-20%。

| 任务 | 贵的方案 | 便宜的替代 | 何时用便宜 |
|---|---|---|---|
| 分类 | `gpt-4o` | `gpt-4o-mini` | 任务定义清晰时总是 |
| 信息抽取 | `gpt-4o` | `gpt-4o-mini` 或 `gemini-2.0-flash` | prompt 明确时 |
| 摘要 | `gpt-4o` | `claude-haiku-4-5` | 新闻、文档、短内容 |
| 代码审查 | `gpt-4o` | `deepseek-v3` | 常规 linting、格式 |
| 客服 | `gpt-4o` | `gpt-4o-mini` | FAQ、工单路由 |
| 创意写作 | `gpt-4o` | `claude-sonnet-4-6`（相近成本） | 速度优先时 |
| 长文档分析 | `gpt-4o` | `gemini-2.5-pro`（1M 上下文） | 避免分片开销 |

**建议**：在 50-100 个真实例子上做并排评测，选满足质量门槛
（如 ≥90% 准确率）的最便宜模型。

## 2. 启用 prompt 缓存

缓存可以给重复的 prompt 前缀带来高达 90% 的折扣。

| 提供商 | 缓存什么 | 如何启用 |
|---|---|---|
| Anthropic | system prompt、工具定义、长文档 | 在 content block 上标记 `cache_control: {type: "ephemeral"}` |
| OpenAI | 长 system prompt（≥1024 tokens） | 跨请求相同前缀时自动 |
| Gemini | system instruction、大文件内容 | 隐式（自动缓存） |

典型客服流程，5,000 token system prompt 在 100 个对话中复用：
- 无缓存：500,000 token 全价计费
- 有缓存：5,000（首次）+ 99 × 500（缓存读）= 54,500 token 全价
  — **节省约 89%**

## 3. 显式设置 `max_tokens`

没设上限时，一个 chat completion 可能生成 2,000+ token 而 100 就够。
始终设置 `max_tokens`（或 `max_output_tokens`）。

```json
{
  "model": "gpt-4o",
  "messages": [...],
  "max_tokens": 500
}
```

## 4. 非紧急工作用 batch API

| 模式 | 延迟 | 折扣 |
|---|---|---|
| 实时 | ~1s | 无 |
| Batch | 最多 24h | 50% |

如果用例能容忍 24h（夜间报告生成、内容审核队列、数据标注），用 batch API。

## 5. 减少输入 token

#1 隐性成本是臃肿的 prompt。

- **删除冗余指令**："be helpful, harmless, and honest" 对大多数模型是隐含的
- **压缩 few-shot 例子**：3 个例子通常够了；多增成本而无质量提升
- **用最小可行的 `temperature`**：对事实性任务（抽取、分类），`temperature: 0`
  更便宜，因为输出更短更确定
- **避免 JSON 模式除非需要**：相同信息下，JSON 输出通常比自然语言
  产生更多 token

## 6. 长生成用流式

对于 UI 应用，设 `stream: true`。token 数量不省，但**按秒计费，
不是按完整请求** — 用户感觉响应更快，长输出场景减少流失。

## 7. 设置 per-key 消费上限

在 dashboard：
- **每月每 key 上限**：硬限制，达到时阻止该 key
- **每 key 速率限制**：防止代码里的死循环

一个 bug 每分钟重试 1000 次持续 1 小时 = 60,000 次请求。
没速率限制的话，预算直接归零。

## 8. 应用层缓存结果

如果两个用户问同样的问题：
- 无缓存：2 次 API 调用，费用翻倍
- 有缓存：1 次 API 调用，费用减半

TTL 建议：
- 事实性 Q&A：24 小时（过期风险低）
- 文档摘要：直到文档变更
- 代码生成：1 小时（过期风险高）

## 成本监控

在 dashboard 设置告警：
- 日消费 > $X
- 单 API key > Y 请求/分钟（异常）
- 4xx 错误率 > 5%（往往是 bug 循环信号）

## 上线前检查清单

新功能上线前确认：

- [ ] 满足质量门槛的最便宜模型
- [ ] 设置了 `max_tokens`
- [ ] 事实性任务 `temperature: 0`
- [ ] system prompt 小于 1,500 token（缓存资格）
- [ ] 配置了每 key 速率限制
- [ ] 重复查询有应用层缓存
- [ ] 错误重试用指数退避（避免重试风暴）
