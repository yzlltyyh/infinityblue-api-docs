title: "Function calling 最佳实践"
description: "可靠、低成本工具调用的模式"
---

Function calling（也叫 tool use）让模型调用你的函数。用得好是放大
器，用得差则浪费 token、混淆模型、产生 broken flow。

## 工具调用结构

```json
{
  "model": "gpt-4o",
  "messages": [...],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get the current weather for a city",
        "parameters": {
          "type": "object",
          "properties": {
            "location": { "type": "string", "description": "城市名，如 'Paris' 或 '北京市'" },
            "unit": { "type": "string", "enum": ["celsius", "fahrenheit"], "default": "celsius" }
          },
          "required": ["location"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}
```

模型返回：

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {
          "name": "get_weather",
          "arguments": "{\"location\": \"Paris\", \"unit\": \"celsius\"}"
        }
      }]
    }
  }]
}
```

你执行函数，把结果作为 `tool` 消息发回，模型继续。

## 最佳实践

### description 写给聪明的实习生看

模型用 `description` 决定**何时**调用函数。差的描述 = 错的调用。

**差**：
```json
"description": "天气函数"
```

**好**：
```json
"description": "Get the current weather for a city. Returns temperature, conditions, and wind. Use when the user asks about weather, temperature, or whether to bring an umbrella."
```

### 严格 JSON schema 早抓错

OpenAI 配 `strict: true` 强制模型输出严格符合 schema：

```json
{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "...",
    "strict": true,
    "parameters": {
      "type": "object",
      "properties": {
        "location": { "type": "string" },
        "unit": { "type": "string", "enum": ["celsius", "fahrenheit"] }
      },
      "required": ["location", "unit"],
      "additionalProperties": false
    }
  }
}
```

没 `strict` 时，模型可能编造字段或漏必填项。

### 用 `tool_choice` 控制行为

| 值 | 何时用 |
|---|---|
| `"auto"`（默认） | 模型决定是否调用工具 |
| `"none"` | 强制不调用（纯文本回复） |
| `"required"` | 强制至少调用一个 |
| `{"type": "function", "function": {"name": "X"}}` | 强制特定工具 |

工作流中**总是**要某个工具时，强制指定它，不要指望模型自己选。

### 执行前验证参数

永远不要盲目信任模型生成的参数。模型可能产生：

```json
{"location": "DROP TABLE users; --"}  // SQL 注入形态
{"location": ""}                       // 空字符串
{"location": null}                     // 必填项为 null
```

执行底层函数前，**始终**在服务端按你的 schema 验证。

### 工具数量控制在 20 以内

每个工具约 50-200 token 占用 prompt（描述 + 参数）。超过 ~20 个工具：
- 成本线性增长
- 模型难以决定用哪个
- 延迟增加

如果需要很多工具，按域分组，每个请求只发相关组（如"日历工具"vs"财务工具"）。

### 并行独立调用

如果模型需要调 `get_weather("Paris")` 和 `get_weather("Tokyo")`，
模型可以在一个响应中返回两个 tool calls。并行执行 — 总延迟 = max，
不是 sum。

```python
import asyncio
from openai import OpenAI

client = OpenAI(...)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[...],
    tools=[...]
)

# response.choices[0].message.tool_calls 可能含多个调用
tool_calls = response.choices[0].message.tool_calls

# 并行执行
results = await asyncio.gather(*[
    execute_tool(call) for call in tool_calls
])

# 一次性把结果发回
for i, call in enumerate(tool_calls):
    messages.append({
        "role": "tool",
        "tool_call_id": call.id,
        "content": json.dumps(results[i])
    })

# 继续对话
next_response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=[...]
)
```

### 限制递归深度

模型可以调工具、拿结果、再调、再拿……没限制的话可能死循环或
token 暴增。

```python
MAX_TOOL_ITERATIONS = 5
for i in range(MAX_TOOL_ITERATIONS):
    response = client.chat.completions.create(...)
    if not response.choices[0].message.tool_calls:
        break
    # 执行并追加
```

## 常见坑

<AccordionGroup>
  <Accordion title="模型用坏 JSON 调用工具">
    `arguments` 字段是需要 `json.loads()` 的字符串。复杂 schema
    下模型可能产生非法 JSON。包 try/except 后重试或让模型修复：

    ```python
    try:
        args = json.loads(call.function.arguments)
    except json.JSONDecodeError:
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": "Error: invalid JSON. Please reformat."
        })
        # 让模型重试
    ```
  </Accordion>

  <Accordion title="模型幻觉一个不存在的工具">
    严格模式有帮助但模型仍可能漂移。dispatch 前验证
    `function.name` 是否在你的已知工具注册表里。
  </Accordion>

  <Accordion title="模型该调用时拒绝调用">
    描述太模糊了。补充更多"何时该调用"的细节。包含会触发的
    示例用户输入。
  </Accordion>
</AccordionGroup>
