---
title: "Apifox 调试沙箱接入"
description: "配置 Apifox 作为开发者试调沙箱，自动从文档仓库同步"
---

Mintlify 文档站自带"Try it"试调功能，但 Apifox 提供更丰富的测试能力：
环境变量、Mock 数据、测试场景、团队协作。本页说明如何让 Apifox 自动从本
文档仓库的 OpenAPI 同步。

## 架构

```
┌─────────────────────────────────────┐
│ GitHub: yzlltyyh/infinityblue-api-docs │
│ openapi/openapi.bundled.yaml (SSOT)   │
└──────────┬───────────────────────┘
           │ Apifox "定时导入" 拉取
           ↓
┌─────────────────────────────────────┐
│ Apifox 项目（自动刷新）              │
│ 公开分享链接                         │
│ apifox.yourgateway.com  （可选）      │
└─────────────────────────────────────┘
```

Apifox 变成我们 OpenAPI 的**消费方**。GitHub 是唯一可信源，Apifox
按计划刷新。无需 CI，无需 token，无需手动重导出。

## 接入步骤

<Steps>
  <Step title="创建 Apifox 项目">
    1. 登录 [apifox.com](https://apifox.com)
    2. 点击 **新建项目** → 命名为 `InfinityBlue API`
    3. 项目类型选 **OpenAPI / Swagger**
    4. 跳过创建时的导入向导（我们下面会设定时导入）
  </Step>

  <Step title="配置定时导入（关键步骤）">
    1. 在新项目里，进入 **项目设置** → **数据管理** → **外部数据源**
    2. 点击 **添加数据源**
    3. 填写：
       - **名称**：`InfinityBlue API Docs (Git)`
       - **类型**：`URL`
       - **URL**：`https://inbllc.mintlify.app/openapi.yaml`
         - 如果你配了自定义域名，改成 `https://docs.yourapi.com/openapi.yaml`
       - **格式**：`OpenAPI 3.0 / 3.1`
       - **同步频率**：每 1 小时
       - **导入行为**：`覆盖`（用新版本替换现有接口）
    4. 点击 **保存**
    5. 点击 **立即同步** 触发第一次导入
  </Step>

  <Step title="验证导入结果">
    同步完成后：
    - 进入项目概览
    - 应该看到 13 个端点按文件夹分类（chat、images、videos、models 等）
    - 检查请求/响应 schema 是否正确导入
    - 检查 `bearerAuth` 是否被识别（Apifox 应自动识别）
  </Step>

  <Step title="配置鉴权环境">
    1. 进入 **环境管理**（左侧栏）
    2. 看到 `生产环境`（默认）和可能的 `开发环境`
    3. 点击 **生产环境** → **鉴权** 标签
    4. **类型** 选 `Bearer Token`
    5. 值留空 — 用户试调时自己填 API key
    6. 点击 **保存**
  </Step>

  <Step title="启用公开分享（可选）">
    1. 进入 **分享**（右上）→ **在线分享**
    2. 开关 **启用分享**
    3. 设置可见性：
       - **公开** — 任何有链接的人都能试调（仅用于公开 API）
       - **密码保护** — 团队内部分享
    4. 复制公开 URL — 这就是你的 `apifox.yourgateway.com` 风格链接
    5. （可选）把这个链接加到 Mintlify 的 `api-reference/*.mdx` 文件
       作为"在 Apifox 中打开"按钮
  </Step>

  <Step title="把公开 URL 记在团队 onboarding 文档里">
    在团队文档或 Mintlify footer 加一行：

    > **在 Apifox 试调**：[https://app.apifox.com/link/your-project-id](https://app.apifox.com/link/your-project-id)
  </Step>
</Steps>

## 维护

定时导入处理所有同步。`git push` 到 `main` 分支后：

1. Mintlify 在 1-2 分钟内重新部署
2. 部署后的 `https://inbllc.mintlify.app/openapi.yaml` 更新
3. 下一次 Apifox 同步（1 小时内）拿到更新

如果关键文档更新后需要**立即同步**：
- Apifox 项目 → **数据管理** → **外部数据源** → 点击 **立即同步**

## 常见问题

<AccordionGroup>
  <Accordion title="为什么我不直接在 Apifox 编辑然后推到 Git？">
    那是旧的 NewAPI 工作流。它把可信源分散在 Apifox UI 编辑和 Git
    提交之间，单向从 Apifox 推到 Git。容易失去追踪哪个是规范。

    这个工作流**相反**：Git 是可信源，Apifox 拉取。所有修改都走
    你正常的 Git review 流程。
  </Accordion>

  <Accordion title="如果 OpenAPI 有错怎么办？">
    Apifox 会导入失败，在数据源历史里显示错误。在 Git 修 OpenAPI，
    push，等 Mintlify 重新部署，然后在 Apifox 点 **立即同步**。
  </Accordion>

  <Accordion title="本地开发呢？">
    本地开发不需要 Apifox。用：
    - `mint dev` — Mintlify 本地预览，OpenAPI 实时渲染
    - `curl` + bundled OpenAPI 作为合约参考
    - 或者把 `openapi/openapi.bundled.yaml` 直接导入本地 Postman/Insomnia
  </Accordion>
</AccordionGroup>
