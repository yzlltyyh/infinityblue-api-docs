For video generation, polling `GET /v1/videos/{task_id}` is the
default. For production at scale, **register a webhook** to receive
completion events as soon as the model finishes — saves you 30s-3min
of polling per task.

## Register a webhook

1. Dashboard → **Webhooks** → **Add endpoint**
2. Enter your URL (must be HTTPS)
3. Select events: `video.task.completed`, `video.task.failed`
4. (Optional) Add a signing secret for HMAC verification

## Payload format

When a video task completes, we POST to your endpoint:

```http
POST /your-webhook-endpoint HTTP/1.1
Content-Type: application/json
X-InfinityBlue-Signature: t=1700000000,v1=abc123...
X-InfinityBlue-Event: video.task.completed
User-Agent: InfinityBlue-Webhook/1.0

{
  "event": "video.task.completed",
  "created_at": 1700000000,
  "data": {
    "id": "video_abc123def456",
    "object": "video",
    "model": "seedance-2.0",
    "status": "completed",
    "progress": 100,
    "created_at": 1700000000,
    "completed_at": 1700000120,
    "expires_at": 1700003720,
    "seconds": "5",
    "size": "1280x720",
    "url": "https://cdn.infinityblue.com/videos/abc123.mp4",
    "metadata": {
      "seed": 12345
    }
  }
}
```

For failures:

```json
{
  "event": "video.task.failed",
  "created_at": 1700000000,
  "data": {
    "id": "video_abc123def456",
    "object": "video",
    "model": "seedance-2.0",
    "status": "failed",
    "progress": 30,
    "created_at": 1700000000,
    "seconds": "5",
    "error": {
      "code": "content_policy_violation",
      "message": "Prompt was blocked by content filter"
    }
  }
}
```

## Verify the signature

We sign every webhook with HMAC-SHA256. Always verify before
trusting the payload.

```python
import hmac
import hashlib

def verify_webhook(payload_bytes, signature_header, secret):
    """
    payload_bytes: the raw request body (bytes, not parsed JSON)
    signature_header: the value of X-InfinityBlue-Signature header
    secret: your webhook signing secret
    """
    # Format: "t=1700000000,v1=signature_here"
    parts = dict(p.split("=") for p in signature_header.split(","))
    timestamp = parts["t"]
    received_sig = parts["v1"]

    # Reject if timestamp is more than 5 minutes old (replay protection)
    if abs(time.time() - int(timestamp)) > 300:
        return False

    # Recompute signature
    signed_payload = f"{timestamp}.".encode() + payload_bytes
    expected_sig = hmac.new(
        secret.encode(),
        signed_payload,
        hashlib.sha256
    ).hexdigest()

    return hmac.compare_digest(received_sig, expected_sig)
```

## Return 2xx to acknowledge

Your endpoint must return `2xx` within 5 seconds. If we don't get
2xx, we retry with exponential backoff:
- Retry 1: 1 minute later
- Retry 2: 5 minutes later
- Retry 3: 30 minutes later
- Retry 4: 2 hours later
- After 4 retries: dead-letter queue (visible in dashboard)

To safely retry without duplicates, the `data.id` is unique per
task — make your handler **idempotent** (same `id` arriving twice
= same action).

## Common pitfalls

<AccordionGroup>
  <Accordion title="I'm not receiving any webhooks">
    Check:
    1. Your endpoint returns 2xx within 5s
    2. Your endpoint is HTTPS (HTTP endpoints are rejected)
    3. The webhook is registered for the right events
    4. The dashboard's webhook delivery log doesn't show a failure
  </Accordion>

  <Accordion title="Signature verification fails">
    Two common causes:
    1. You signed the parsed JSON instead of the raw bytes. Always
       sign the raw body. JSON serialization can reorder keys or
       add/remove whitespace.
    2. Your timestamp tolerance is too tight. ±5 minutes is standard.
  </Accordion>

  <Accordion title="I get the same webhook 4 times">
    Your endpoint is returning a non-2xx status (or timing out). Check
    the dashboard's delivery log for the response code and timing.
    Make sure to return 2xx quickly (ideally before doing real work —
    queue the task and return).
  </Accordion>
</AccordionGroup>

## Best practice: queue the work

Don't process the webhook synchronously. Return `200 OK` immediately
and put the work in a queue:

```python
@app.post("/webhooks/infinityblue")
async def handle_webhook(request: Request):
    payload_bytes = await request.body()
    sig = request.headers["X-InfinityBlue-Signature"]

    if not verify_webhook(payload_bytes, sig, WEBHOOK_SECRET):
        raise HTTPException(401, "Invalid signature")

    # Parse and queue, don't process synchronously
    event = json.loads(payload_bytes)
    await redis.enqueue("video-completed", event)

    return {"ok": True}  # 2xx in <100ms
```

A worker process then picks up the queue, downloads the video from
`data.url`, stores it in your own S3, updates the database, sends
a notification to the user, etc.
